# 회부: 1GB 서버가 1분 수집 + 시간별 집계를 못 버틴다

## 상황
- Oracle Free: **2 vCPU / 956MB RAM / 45GB**, 스왑 없음(확인 필요)
- cron 1분마다 `collect.py` — 거래소 10 × 종목 20 × 규모 5 × 매수매도 = **2,200행/라운드**, 20초 소요
- 매시 00~02분에 `agg.py` → `history.py` → `build_report.py`
- 원시는 **시간별 파일**(gzip csv). 1분 간격이면 파일당 60라운드 = **132,000행**
- `agg.py` 는 최근 24시간 = **24파일을 전부 pandas 로 읽어 concat** → 약 **3.2M 행**
- 5분 간격일 때는 파일당 12라운드(26,400행), 24파일 = 634,000행이라 버텼다
- **1분으로 바꾼 뒤 서버가 ssh 조차 응답하지 않는다**(banner exchange 타임아웃).
  sshd 는 살아 있으나 응답이 안 온다 → 메모리 압박으로 추정

## agg.py 가 하는 일
1. 24개 파일 읽어 concat (모두 메모리)
2. 24시간 밖 행 잘라내기
3. `groupby(['venue','coin','usd_size'])` 로 중위·분위·체결률
4. 스파이크: 같은 키로 transform('median') → 초과분 계산
5. 시계열: 4조합(BTC/ETH/XAU/NVDA @ $100k)만 pivot
6. JSON 출력(0.4MB)

즉 **원시 전체를 메모리에 올려야 하는 구조**다.

## 목적
- "GRVT 가 유동성 경쟁에서 어디쯤인가"에 정직하게 답하는 공개 리포트
- 최근 추가한 핵심이 **스파이크 관측** — 그래서 조밀한 표본을 원했다
- 사용자: "꼭 1분 안 지켜도 된다. 최대한 원활하게 좋은 절충안을 달라"

## 내가 떠올린 선택지
- A) 수집을 2~3분으로 낮춘다 (표본 절반~1/3)
- B) 집계를 **증분**으로 — 매시간 그 시간 파일만 요약해 두고, 리포트는 시간별 요약 24개를 합친다
- C) 원시를 라운드별 요약(거래소×종목×규모 중위)만 남기고 개별 관측은 버린다
- D) pandas 메모리 최적화 — dtype 축소(float32/category), 파일별 순차 처리 후 합치기
- E) 스왑 파일 추가 (45GB 디스크 중 2GB)
